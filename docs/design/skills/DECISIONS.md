# Skills redesign decisions

1. Authorization: the owner's 2026-11-20 request explicitly authorizes all listed study skills, meetings and document generation, UI work across all four steps, and proceeding without intermediate approvals. This task-specific request supersedes the standing study-tool exclusion and per-phase approval pauses for this task only. Existing alarm/call/STT/TTS reliability and repository safety rules still apply.
2. Branch `codex/skills-hub` starts at the current development descendant `df573ba`; `agy-development-cont` (`b9433dc`) is its ancestor. Existing uncommitted authentication/voice/onboarding work is preserved and excluded from task commits. No resets, stashes or writes to sibling repos.
3. Reference HTML and 17 original PNGs are preserved under this folder. `reference-pages/` is a literal extraction of `window.__PAGES__`, retained for inspectable geometry, CSS and logic. Reference scripts are design examples, not implementation authority: their mock data and timed fake AI completions will not be copied into the app.
4. The in-app browser security policy rejected the local `file:` HTML URL. No alternate browser or indirect serving workaround was attempted. Source/PNG review is available; interactive browser verification remains NOT RUN.
5. Reference geometry maps 1 CSS px to 1 dp; accessibility expands targets smaller than 44 dp and layouts grow/scroll under large fonts. Semantic app theme roles replace reference-only purple/light colors so all current light/dark/Modern palettes remain supported.
6. Existing persisted `notes` tab ID, `tools-*` tour IDs and old navigation targets stay stable. The Skills hub pushes subpages inside the existing retained tab architecture and handles Android Back; its scroll container stays mounted while subpages are open.
7. Existing Alarms/To-do/Notes models, stores, scheduling, notifications and AI hooks stay unchanged; only their UI host/presentation changes. No schema migrations. New skill state uses versioned, owner-scoped keys in the existing `local_settings` table, with visible persistence errors.
8. New AI skills use `onlineChatSkill` / `documentSkill` and respect the existing `chat.onlineMode` preference, account/consent and backend entitlement checks. Outputs are validated before use. Offline, missing capability and errors show honest messages; nothing generates placeholder answers.
9. GWA is an estimate using owner-requested 1.00–5.00 range and 0.25 controls; ungraded subjects are excluded, zero units never divide by zero, no official academic eligibility decision is made. Imported COR credit units are used when available. No portal integration.

10. The owner confirmed that phone checks can be performed manually and Android Studio is unnecessary. No app was installed, no phone data was cleared, and no OS permission was changed during this task. A standalone ARM64 `dataQa` APK is provided for review; this build bundles JavaScript and uses the existing backend without provider-test secrets.
11. The requested focus-silence switch uses a separate native timer module and optional `ACCESS_NOTIFICATION_POLICY` permission. Access is requested only through the Android settings page after an explicit switch action. Focus silence permits alarms and restores/deactivates LAFINA's DND rule on pause, reset, skip or session end. Existing reminder and clock-alarm registries are untouched. The architecture allowlist records this task-specific permission with this rationale.
12. AI jobs survive navigation in the running app and expose actual stages. They do not claim to survive process termination. Quiz answers, generated summaries, decks, grades and completed document metadata persist locally. Consumed job results cannot overwrite subsequently saved quiz progress.
13. Existing document generation accepts a 4,000-character prompt. Its builder allocates a maximum 2,500-character source budget after preserving revision instructions and verified Handbook references. The UI discloses this limit. Revisions preserve the original requested format and original request; previous output is regenerated using its summary and available source context, not edited in place.
14. Explicit capability gates: live meeting transcription, embedded Office page/slide rendering, and DOCX source extraction are false. Meetings offers finalized Whisper transcripts, real PCM-level waveform, summary and reviewed to-do creation. Documents offer the actual generated file plus a summary preview and native Open/Share. Text-based PDF source extraction uses the existing first-page extractor and tells the student when a PDF has more pages. No mock transcript, fake files, timed AI result or sample study content is shipped.
15. Classic and all six Modern themes retain their hues and semantic surfaces. Skills derives readable text/action tones and action foregrounds from those roles. Contrast tests cover Classic plus every Modern theme in light and dark. Four Lexend font files come from the supplied prototype; the official SIL OFL accompanies them. Native switches and expanded touch targets are deliberate accessibility adaptations.
16. The existing `notes` tab identifier and `tools-*` tour identifiers stay unchanged. There was no exported `tools` URI handler in the original manifest; existing local call/Quick Chat targets (`notes`, and legacy calendar alarms) are preserved. No old route or storage key was renamed. Internal assistant tool API fields and imports named `tools` remain technical identifiers.
17. Source and unit/component checks can establish preserved contracts and working tested flows. They do not establish a pixel-perfect native rendering, TalkBack behavior, hardware audio, alarm delivery, force-stop/reboot behavior, or production account entitlement. Those remain explicitly listed for phone review; no benchmark results are invented.

18. Further edits to the alarm card rendering and its test appeared concurrently during the final accessibility check. They are preserved as separate working-tree changes; the Skills commit stages only its switch touch target. Final verification/APK describe the current checkout, including unrelated in-progress work, not a claim that those edits belong to the Skills implementation.
