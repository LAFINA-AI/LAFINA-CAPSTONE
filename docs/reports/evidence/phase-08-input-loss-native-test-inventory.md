## Critical entry/cleanup distinctions for the root case runner

- **A28 / `review-pause`:** source first opens the private reminder, prepares ACK review, retains the stale confirmation node, resumes MainActivity and attempts that old node, then sets a known unsent QA08 draft. It calls `ReminderNotificationUiTest.openOwnedNotification()`, which verifies the exact owned notification, opens `GLOBAL_ACTION_NOTIFICATIONS` and clicks its actual SystemUI body. It then requires new Answer/review, reopens MainActivity, verifies the unsent draft survived, and clears only that exact test draft. This is real notification reopening, not another private-intent reopen. See `ReminderLifecycleUiTest.kt`160–247 and `ReminderNotificationUiTest.kt`72–118.
- **A13 / `remove-main-task`:** source verifies MainActivity is RESUMED, finds exactly one app-owned task with exact MainActivity base+top, invokes `AppTask.finishAndRemoveTask()` on that task, then verifies that task ID left the app-owned task list. It is explicitly labelled `APP_OWNED_TASK_API_NOT_RECENTS_GESTURE`; it is neither a Recents swipe nor force-stop/process-death proof.
- **`review-delete-source`:** source prepares an ACK review, retains the old Confirm node, resumes MainActivity, refuses unknown composer drafts/reviews, enters exactly `Delete task "<owned QA08 title>"`, sends and explicitly confirms through Chat, then attempts the old native confirmation node. No direct SQLite write or arbitrary row deletion is made. Root must verify soft-removal, task/reminder fences and cleanup independently. Soft-removal retains text/history/receipts; it is not permanent erasure.
- **A27:** the current driver adopts only the audio-mode-changing test permission after actual Recording. Its expected interrupted state accepts the production cancellation message with AUDIO_INTERRUPTED/AUDIO_FOCUS_LOST; a precondition failure does not pass the interruption assertion.
