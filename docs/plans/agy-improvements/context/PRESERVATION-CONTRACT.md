# Protected AGY feature contracts

These capabilities are owner-approved and must remain reachable and working. Preserve intentional existing role restrictions and consent, not accidental leaks or fabricated success. This plan does not add a new payment provider or make unauthorized entitlement changes.

In Phase 00 create reports/PRESERVED-FEATURES.md and characterization tests covering each ID. Keep original suites; add focused integration tests around seams the port changes. A mock is appropriate for deterministic cloud contracts but must not be described as a live service test.

## Definition of a preservation regression

A reachable capability disappears, becomes permanently disabled, gets an incorrect role gate, loses data, sends a changed incompatible payload, bypasses consent, changes speech defaults, produces duplicate delivery, or is mocked away so old tests no longer exercise it. These are failures even if the new improvement's tests pass.

Purposeful safety improvements may add review/confirmation to assistant-proposed planner/Notes mutations, conflict feedback, pagination and accurate unavailable states. Preserve manual CRUD, contextual ringing-call ACK/snooze, document generation and recording gestures. Record such intentional differences by PF ID instead of calling every UX change a regression.

## Mandatory matrix fields

For every PF ID record baseline command/test and result, touched seams, final command/test and result, live/device status, and any intentional change/deferred limitation. Use PASS/FAIL/NOT_RUN explicitly. Test existence, code reachability and suite file counts alone cannot establish a feature pass.
